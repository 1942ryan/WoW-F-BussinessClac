## 确认采用语义（用户困惑点，已实验实证 + 固化测试）
- 语义 = 优先权 + 次数上限：当前技能下可用（已解锁未变灰）的确认配方优先做（哪怕不是最便宜）；
  次数 N 是**上限不是目标**，做完退出路线。系统绝不会因填 N 而多做。
- 用户「填了数量结果没变」的三种原因（server 1 锻造 1→100 API 实验）：
  a) 确认的配方本来就会被选中且所需次数 ≤ N → 上限不触发，路线不变（确认「粗制平衡石」999 → 与基线完全一致）
  b) 确认的配方当前技能段不可用（未解锁/已变灰）→ 完全无效（确认「镀银青铜胸甲」橙105 冲1→100 → 与基线一致）
  c) 默认 1 次：多数配方确认后只做 1 次就退出——这种是会变化的（变少）
- 生效场景：强制优先做非最便宜配方（确认+大次数）；长 CD 配方按周期可做次数填
- 新增测试：test_confirmed_count_is_cap_not_target / test_confirmed_no_effect_when_unavailable /
  test_confirmed_priority_over_cheaper（60 个 pytest 全过）
